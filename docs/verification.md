## 通知与筛选边界

- **默认规则**：赛事级别为 S/A，赛前提前 10 分钟，赛程每 5 分钟刷新，未来获取范围为 2 天；关注优先默认开启，黑名单优先排除。关注战队不会自动关闭其他符合级别的比赛。只看关注队伍时，可在面板清空赛事级别并保留关注优先。
- **多群管理**：每群可独立设置战队、等级、黑名单、提醒时间和日报；未自定义项目继承默认值。暂停群不会影响其他群，查询仍可按本群规则进行。`push_platform_id` 继续指定一个普通机器人实例。
- **赛前复核**：发送前重新获取单场状态、对手与时间；取消、延期、TBD 或无法核实的比赛不使用旧缓存直接提醒。赛前失败会在开赛前窗口继续尝试；已知比赛提前开赛后由赛果追踪衔接补报。
- **改期通知**：双方队伍确定，状态为未开赛且新时间仍在未来，旧或新开赛时间距当前不超过两小时，或已经发送过赛前提醒，才符合条件。同一时间的格式／时区表示变化，以及分钟内的精度变化，不产生可见通知。每个群待收的同批改期 1–2 场逐条发送、3 场及以上汇总；失败群重试，远期或 TBD 变更不会等临近后再补发旧变更。
- **日报恢复**：只处理运行期间观察到的定时点，恢复当天仍有效的 pending 事件，冻结原始内容并重试未成功的群；不补齐停机期间全部错过的日报，无群或无可推赛程的事件会跳过。手动 `/cs推送` 不建立定时日报重试任务。
- **赛果恢复**：待处理比赛与截止时间持久化。正常轮询窗口约 6 小时；前 6 次间隔 5 分钟，之后 15 分钟。重载恢复受计划开赛后 24 小时边界及有限补查窗口约束；具体判断见 `main.py` 的 `_restore_result_polls` 与 `_run_result_poll`。这些参数不能解释为全天候即时战报承诺。
- **去重边界**：按通知事件与群保存回执。发送已成功但回执尚未落盘时中断，仍可能重发；重建提醒、清空记录等操作也会改变后续发送状态。改期待发队列未持久化，重启后不能保证恢复尚未送达的改期通知。
- **数据与请求**：赛程和赛果来自 PandaScore；HTTP 429、5xx 或网络异常会进行有限重试，普通永久性 4xx 不循环重试。账户权限、额度、网络、赛程缺失和数据延迟都会影响结果；不承诺覆盖全部赛事或实时更新。
- **界面操作**：赛事查询与预览只展示结果，不群发，也不因查询创建主动通知；读取缓存或生成图片仍可能发生。面板“测试”会实际发送到测试目标，“正式推送”会发送到正式接收群。

## 本次执行的离线检查

2026-11-03，在已有 Python 3.13.5、aiohttp 3.14.4、Pillow 12.3.0 环境运行现有及新增的离线测试。新环境先安装依赖，再运行测试；本次使用已有依赖执行下面的第二条命令：

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p 'test_*.py' -v
```

测试结果：**48 项通过**，包括群规则 35 项、改期 8 项、提前开赛 5 项。测试替代 AstrBot 宿主、PandaScore 请求和 QQ 发送端，实际执行规则、调度、存储、图片缓存和本地 HTTP 接口，覆盖：

- 每项继承、明确关闭与空列表、分钟边界、黑名单优先及战队 ID 筛选。
- 用户自定义的不同提醒分钟数、单场优先级、未来新群加入、已过提醒不追补、共用一条赛果追踪。
- 分群赛果开关、部分失败重试、目标冻结、发送前暂停检查、并发渲染隔离与落盘失败恢复。
- 每群改期资格、汇总数量和图片模式；日报独立时间、内容冻结、重载恢复及旧版完成／部分成功事件迁移。
- 开幕时间、查询范围、真实 PNG 缓存隔离、Major 图片覆盖、测试目标隔离、配置导入导出、接口鉴权与群参数校验。
- 原有提前开赛补报、终态排除、改期窗口、临时请求失败及任务恢复回归。

基础检查确认 29 个根目录 Python 文件、7 个 JSON 文件和 3 个管理页 JS 文件通过语法／格式解析。

本地 Chromium 另外完成 14 项页面流程检查，覆盖选择群、自定义分钟数、关注搜索、独立开关、多个日报时间、复制隔离、保存、放弃、范围校验、恢复继承、指定群预览、390px 手机布局、暗色主题与模拟内嵌 bridge。使用本地替代接口，没有打开真实 AstrBot 或 QQ 界面，也没有发送消息。

这些结果不等于真实 AstrBot／QQ／PandaScore 端到端验收，最低宿主版本和官方账号权限仍需在实际环境确认。旧提交的 CI 结果不作为当前版本的测试证明。

## 手动验收与待补证据

以下是可复现步骤，**不是本次已执行结果**。维护者应在自己的测试部署中使用专门的测试群和非公开凭据，记录 AstrBot 版本、Python、适配器、插件提交、日期和脱敏日志。

1. 安装依赖并配置 PandaScore Token，重载后用 `/cs状态`、`/cs比赛` 核对数据连接、筛选和获取范围；再用 `/cs赛果 3` 核对计划开赛日期口径。
2. 在「插件详情 → CS2 管理」完成引导、添加两测试群，分别选择不同关注战队、提醒分钟数和日报时间并统一保存；刷新页面核对保存结果，截取概览、订阅和推送页。独立面板无有效令牌访问 `/api/config` 应返回 401。
3. 先查看预览，核对没有消息发出；明确选好测试目标后再使用测试发送，核对该目标收到图片、正式群未被本次测试发送影响。截图应遮盖群号、Token、令牌和后台地址。
4. 在测试部署用可控数据或离线替身复现三场临近改期、一群失败及重试，核对成功群不重复、各群只收到本群匹配的通知。现有测试可复现判断逻辑；如要证明真实投递，另保存两群收到的消息及脱敏日志。
5. 查询 `/cs对阵图 瑞士轮` 和 `/cs对阵图 淘汰赛`，记录实际届次与数据时间，确认未知对阵保持待定；未收录届次应诚实提示，不能以历史截图冒充实时数据。
6. 接入并启用官方扩展，只开放部分查询，核对功能按钮、当前会话回复及富回复失败回退；在官方侧尝试管理指令应拒绝，不能改变普通端配置。对 `qq_official` 与 `qq_official_webhook` 分别记录结果。
7. 两个用户抽取今日选手，重复请求应保持原结果；在两适配器使用不同身份分别抽取不算同一自然人的去重测试。重载后核对 SQLite 记录保留。

完成后可补充最小／推荐 AstrBot 版本、适配器版本及实际截图；目前不填写未经验证的 `astrbot_version` 门槛，也不宣称所有 AstrBot 4.x 兼容。

## 备份与恢复范围

数据目录为 `data/plugin_data/astrbot_plugin_cs_match/`。建议停用插件后复制整个目录，至少保留 `cs_data.json` 与已生成的 `qq_daily_players.sqlite3`。前者含配置和通知状态，后者含当日选手分配。面板导出的配置排除了凭据、通知记录、待处理状态，也不包含抽签数据库，不能替代完整备份。

升级保持 `astrbot_plugin_cs_match` 标识与数据目录。恢复时使用同一插件身份，先核对配置与通知状态，再恢复运行；复制出来的凭据和数据库不应作为公开使用案例上传。
